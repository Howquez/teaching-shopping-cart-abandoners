# Research Compendium and Teaching Materials "Does the Cart Reminder Email Pay Off?"

## Overview

This replication package evaluates a fictional cart abandonment email campaign. The code in this package simulates the raw data, cleans and merges four messy data exports, estimates the causal effect of the email against a randomized holdout, evaluates its economic value, and runs a simulation-based power analysis. One main file (`_run_all.R`) runs all steps and renders a three-page PDF report with 3 figures and 1 table. The replicator should expect the code to run for less than one minute, plus the time groundhog needs to install packages on first use.

All results are computed by plain R scripts with few dependencies (`data.table` and `here`, pinned with `groundhog`). The report is written in Quarto, which combines text and code in one document (literate programming): every number in the text is computed directly from the saved results instead of being copied by hand. Quarto adds dependencies of its own (Quarto, `knitr`, `rmarkdown`, and LaTeX), so it does not make the analysis more computationally reproducible. Its benefit is traceability: each number in the report can be traced back to the code that produced it, which rules out copy and paste errors. If the report cannot be rendered, all results can still be reproduced with the R scripts alone, and the figures and tables are available in `outputs/`.

The package is designed as a teaching resource on computational reproducibility, data cleaning, causal inference with a holdout group, and statistical power. All data are simulated.

### Details on the Data Source

All data were generated by the author with `scripts/00_simulate_raw_data.R`. They describe a fictional online shop and contain no information on real persons or companies. The simulated raw data are provided in `data/raw/`, so the simulation does not need to be rerun to reproduce the results. Variables are documented in `codebook.md`.

**Simulation design.** The script simulates 60,000 customers of an online shop in Germany, Austria, Switzerland and the Netherlands between 1 September and 31 October 2026. Each customer has a latent purchase intent that drives browsing, cart additions and purchases. Customers who abandon a cart for the first time and have a known email address enter the campaign; 10% of them are randomly assigned to a holdout that receives no email. The email raises the probability of ordering within seven days by a small amount. Purchases of customers who would have bought anyway are also generated, which is why naive comparisons overstate the effect.

The script then writes the data as four realistic, deliberately messy exports (CRM, web analytics, ERP, email tool) plus the summary metrics of a vendor dashboard. The messiness includes duplicates, test accounts, bot sessions, inconsistent labels, mixed date formats, German number formats, different time zones, and variables that are irrelevant for the analysis. The script also writes `instructor_only/answer_key.txt`, which contains the true parameters, the effect a clean analysis should recover, and a list of all data problems built into the data.

> **Spoiler warning for students:** The simulation script and the answer key reveal the true effect and all traps in the data. We recommend working through the analysis before opening them.

Rerunning the simulation with the same seed reproduces the provided raw data exactly. Their fingerprints are recorded in `outputs/logs/data_checksums.txt`. Other seeds produce other realizations of the same true effect, which can be used to illustrate sampling variability.

## Description of programs/code

All scripts are in `scripts/` and are numbered in the order in which they run.

- `scripts/00_simulate_raw_data.R` simulates the raw data and the answer key (see above). It is not part of the standard pipeline, because the raw data are provided.
- `scripts/01_read_data.R` reads the four raw exports, cleans them, and merges them into `data/processed/analysis_data.csv`. Every cleaning step prints its consequences (rows removed, values recoded) into the log file.
- `scripts/02_analyze.R` computes the conversion rates reported by the vendor, the causal effect of the email (treatment vs. holdout), a regression-adjusted estimate, and the economic value. Business assumptions (margin, email cost) are set at the top of the script. Results are saved to `outputs/results/analysis_results.rds`.
- `scripts/03_power_simulation.R` runs a simulation-based power analysis and illustrates the winner's curse. Results are saved to `outputs/results/power_results.rds`.
- `scripts/04_figures_tables.R` turns the saved results into figures (`outputs/figures/`) and tables (`outputs/tables/`).
- `report/report.qmd` renders the report `report/report.pdf`. All numbers in the text are computed with inline code from the saved results.
- `_run_all.R` runs scripts 01 to 04 in fresh R sessions, renders the report, and writes all logs to `outputs/logs/`.

## Instructions to Replicators

1. Open `cart_abandonment.Rproj` in RStudio. This sets the working directory to the project root, which the scripts rely on.
2. Install `knitr` and `rmarkdown` (see above), Quarto, and TinyTeX (`quarto install tinytex` in a terminal).
3. Run `_run_all.R`.
4. Compare `report/report.pdf` and the logs in `outputs/logs/` with the provided versions.

Optional: To regenerate the raw data, run `scripts/00_simulate_raw_data.R` before step 3 and compare the checksums of the new files with `outputs/logs/data_checksums.txt`.

### Details on the logs

`_run_all.R` writes the following files to `outputs/logs/`. They document the last complete run on the author's machine.

| File | Content |
|---|---|
| `01_read_data.Rout` to `04_figures_tables.Rout` | Every line of code with its output, warnings and errors; package versions and run time at the end |
| `report.log` | Messages and errors from rendering the report |
| `data_checksums.txt` | MD5 fingerprint of each raw data file |
| `quarto_version.txt` | Quarto version used to render the report |
